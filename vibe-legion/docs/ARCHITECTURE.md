# Архитектура и решения

## Поток данных

```
 Media Foundation (поток захвата, EcoQoS)
   SourceReader, MF_LOW_LATENCY, NV12/YUY2/L8/L16
        │  копия кадра → FrameMailbox (один слот, старое перезаписывается)
        ▼
 VisionPipeline (свой поток, частота 1 / 4 / 30 к/с)
   NV12 → RGB (зеркально), ночное усиление или ИК-селектор
   YuNet лица (каждый кадр в ожидании, 3 р/с при руке) ─┐ SFace раз в 2 с
   кисть: трекинг ROI по прошлым точкам; не нашли →     │ (лениво, выгружается)
          детектор ладони → ROI → 21 точка (2D + 3D)    │
   поза, свой шаблон (3 ближайших), взмах ──────────────┘
   GestureEngine: удержание, кулдаун, грейс 160 мс, лица
        │ PostMessage                   │ снимок (мьютекс), 2–15 Гц
        ▼                               ▼
 App (UI-поток): SendInput / ShellExecute, журнал, OSD, трей; окна Direct2D
```

Задержка «камера → действие»: кадр берётся из ящика сразу, в очереди ничего не копится.
Отсюда задержка ≤ периода кадра + ~7 мс обработки + время удержания из правила.

## Чем отличается от выжимки Gemini и почему

Выжимка была отправной точкой, но часть её не подходит этому ноутбуку или противоречит цели
«минимум энергии». Обязательным было только требование C++.

| Выжимка | Сделано | Почему |
|---|---|---|
| OpenCV для захвата (`CAP_DSHOW`) | Media Foundation напрямую + ~300 строк своих преобразований | OpenCV добавил бы ~60 МБ DLL и десятки МБ памяти ради трёх функций. MF — родной стек Windows 11 и единственный, который видит ИК-сенсор Hello (`KSCATEGORY_SENSOR_CAMERA`) |
| Отдельный поток захвата против лага буфера | Есть: поток захвата + ящик на один кадр | Конвейер всегда берёт самый свежий кадр, буфер не копится |
| «Только CPU, чтобы RTX спала» | CPU по умолчанию, плюс DirectML и NPU как опции | В 15ASH11 нет NVIDIA: Radeon 8060S встроен в APU. CPU всё равно выгоднее: модели крошечные (2–5 мс на 1 ядро), а будить iGPU или NPU ради них дороже. NPU (XDNA 2) требует ORT из Ryzen AI SDK |
| `ABOVE_NORMAL_PRIORITY_CLASS` всегда | Зависит от профиля: Эко и Баланс — EcoQoS и обычный/пониженный приоритет, «Отклик» — без троттлинга и `ABOVE_NORMAL` | Повышенный приоритет мешает энергосбережению. В играх приложение и так ставится на паузу и отпускает камеру |
| `Dist = K / |p0 − p9|` | Учёта дистанции нет (убран в 0.2) | Окно «60–70 см» скорее мешало: правило переставало срабатывать, стоило сесть чуть ближе или дальше |
| BlazeFace для «пользователь смотрит» | YuNet (5 точек) + поза головы + SFace для узнавания конкретных людей | Нужно было «добавлять другие лица»: для этого нужна модель узнавания и выравнивание по 5 точкам. YuNet весит 230 КБ |
| `sleep_for(300ms)` ≈ 3 к/с без объекта | Три режима (1 / 4 / 30 к/с) + трекинг вместо детектора + полная пауза с освобождением камеры | Детектор ладони — самая дорогая часть, при трекинге он не запускается. Пауза отключает сенсор и USB, а не только наш код |
| Dear ImGui (DX11) | Своё immediate-mode GUI на Direct2D со стилем Fluent | ImGui не выглядит как Windows 11. D2D даёт Mica, Segoe UI Variable и Fluent Icons без зависимостей. Окно уничтожается при закрытии |
| vcpkg | Готовый архив ORT (по умолчанию) или vcpkg (пресет) | Сборка `onnxruntime` в vcpkg занимает десятки минут, официальный архив скачивается за секунды |

## Модели

| Файл | Вход | Где | Заметки |
|---|---|---|---|
| `palm_detection_mediapipe_2023feb.onnx` | 192×192 NHWC RGB/255, letterbox | только без трекинга | 2016 якорей SSD генерируются в коде; сверены с таблицей OpenCV Zoo (погрешность 1e-8) |
| `handpose_estimation_mediapipe_2023feb.onnx` | 224×224 повёрнутый ROI | каждый активный кадр | выходы: 21×3 экранные, присутствие, рука, 21×3 метрические |
| `face_detection_yunet_2023mar.onnx` | NCHW BGR 0..255 | раз в 0–300 мс | вход зашит 640×640. При загрузке размер патчится в байтах protobuf на 224×128 (оба значения — двухбайтные varint, длины сообщений не меняются), это в ~14 раз меньше пикселей |
| `face_recognition_sface_2021dec_int8.onnx` | 112×112, выравнивание подобием по 5 точкам | лениво, раз в 2 с | вектор 128, косинусное сходство; выгружается через 2 мин простоя |

Модель ждёт зеркальный (селфи) кадр, поэтому конвейер всегда зеркалит. «Лево/право» и
«ладонь к камере» считаются согласованно; на случай расхождения есть переключатель.

## Ночное зрение

1. **RGB-камера.** Скользящая средняя яркости ниже порога → через 1,5 с включается
   программное усиление:
   - временное шумоподавление с порогом по движению (тёмные кадры шумнее, порог растёт);
   - адаптивная гамма к целевой средней яркости;
   - CLAHE 8×5 тайлов с билинейной интерполяцией;
   - усиление применяется к RGB через коэффициент яркости, оттенок сохраняется.

   Одновременно через `IAMVideoProcAmp` поднимаются усиление сенсора и компенсация
   подсветки, а исходные значения восстанавливаются, когда снова светло.
2. **ИК-сенсор Hello.** Если темно дольше 4 с, а сенсор найден, источник переключается на ИК.
   Подсветка включается через `IMFExtendedCameraController`
   (`KSPROPERTY_CAMERACONTROL_EXTENDED_INFRAREDTORCH`; есть только в SDK MSVC, в остальных
   сборках подсветкой управляет драйвер). Если сенсор чередует кадры с подсветкой и без,
   берутся кадры с подсветкой, а из них вычитается кадр без неё: солнце и лампы не мешают.
   Раз в 90 с проверяется цветная камера: не стало ли светло.
3. **Шторка или клавиша отключения камеры.** Почти чёрные кадры дольше 1,5 с дают статус
   «Камера закрыта» и уведомление.

## Энергопотребление: что именно сделано

- Захват: поток с `ThreadPowerThrottling` (EcoQoS), 640×360 (меньше нагрузка на USB и ISP),
  кадр копируется в переиспользуемый буфер, свежих аллокаций нет.
- ONNX Runtime: `intra_op.allow_spinning = 0` (иначе пул потоков крутится вхолостую),
  1 поток, последовательное исполнение, без BFC-арены (−11 МБ памяти, проверено замером).
- Конвейер: таймер кадра вместо постоянного ожидания; без руки — детектор раз в 250 мс;
  без людей — раз в секунду; SFace загружается только если он нужен.
- Система:
  - `WTSRegisterSessionNotification` (блокировка), `GUID_CONSOLE_DISPLAY_STATE` (экран выкл.),
    `SHQueryUserNotificationState` (полноэкранная игра) — в этих случаях камера отпускается;
  - `GUID_ACDC_POWER_SOURCE` и `GUID_POWER_SAVING_STATUS` включают режим «Эко» на батарее;
  - `SetProcessInformation(ProcessPowerThrottling)` в режимах Эко и Баланс.
- UI: перерисовка только по событию; таймер анимаций живёт, пока что-то анимируется; окно
  уничтожается при закрытии, после чего вызывается `SetProcessWorkingSetSize(-1, -1)`.
