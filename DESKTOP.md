# Переработка на десктоп — план

Документ описывает, что уже сделано в 0.4.0, и что осталось до полноценного
десктопного приложения. Порядок — по убыванию отношения «польза / риск».

## Что уже готово (фундамент)

| Компонент | Файл | Зачем для десктопа |
|-----------|------|--------------------|
| Определение платформы | `lib/platform/platform_info.dart` | единственное место с `dart:io Platform`; остальной код не знает, где он работает |
| Брейкпойнты | там же, `Breakpoints` | одинаковые пороги во всех экранах, `isMasterDetail(width)` = 1180 px |
| Master–detail | `lib/screens/catalog_screen.dart` | сетка + панель детали вместо модального листа |
| Переиспользуемая карточка записи | `ItemDetailView` в `item_detail_sheet.dart` | один виджет для мобильного листа и десктопной панели |
| Горячие клавиши | `lib/main.dart` (`Shortcuts` + `Actions`) | `Ctrl+F/R/1…4`, `Esc` |
| Headless-режим | `main(List<String> args)` → `--headless-sync` | системная задача обновляет каталог без окна |
| Дисковый кэш картинок | `lib/services/image_cache_service.dart` | `path_provider` работает на всех десктопах |
| Шаблоны системных задач | `tool/desktop/` | реальное ежедневное обновление на Windows и Linux |
| Размер и заголовок окна | `tool/post_create.dart` | 1280×820 сразу попадает в master–detail |

## Этап 1 — окно и запуск (1–2 вечера)

1. `window_manager` — минимальный размер окна (960×640), сохранение позиции и
   размера между запусками, запрет схлопывания в мобильный layout.
2. Сохранение состояния окна в `SharedPreferences` (`window.x/y/w/h`).
3. `launch_at_startup` — автозапуск, спарить с переключателем в настройках
   (ключ `autoLaunch` в i18n уже есть).
4. Проверить, что `--headless-sync` не поднимает окно на Windows: собрать как
   консольное приложение или использовать `FreeConsole`.

**Риск:** плагины `window_manager`/`launch_at_startup` тянут нативный код —
проверять на всех трёх ОС, каждый вызов оборачивать в try/catch по образцу
`BackgroundWorker`.

## Этап 2 — десктопные привычки (2–3 вечера)

1. **Трей** (`tray_manager`): свернуть в трей, «Обновить сейчас», «Открыть»,
   «Выход». Тогда слой 2 расписания работает всегда, а слой 3 нужен только
   когда приложение полностью закрыто.
2. **Контекстные меню** по правой кнопке на карточке: копировать ссылку,
   копировать контекст для AI, открыть в браузере, в избранное.
3. **Навигация с клавиатуры**: `↑/↓/←/→` по сетке, `Enter` открывает,
   `Tab` между панелями. Требует `FocusTraversalGroup` вокруг сетки.
4. **Drag & drop** (`desktop_drop`): бросить `catalog.json` в окно → импорт
   пользовательских записей.

## Этап 3 — то, чего нет на телефоне (3–5 вечеров)

1. **Экспорт в файл** вместо буфера обмена: `file_selector` уже в зависимостях,
   добавить «Сохранить контекст для AI как .md» и «Экспорт каталога .json».
2. **Массовые операции**: множественный выбор карточек → один markdown-файл с
   контекстом для агента. Это главный сценарий, ради которого каталог вообще
   открывают на десктопе.
3. **Локальный HTTP-эндпоинт** (`localhost:8787/context?id=…`) — тогда Claude
   Code и Codex смогут дёргать каталог напрямую как источник контекста.
   Слушать только `127.0.0.1`, включать по флагу в настройках.
4. **CLI**: `vibestack_atlas --search "free database" --json` для скриптов.

## Этап 4 — упаковка

| ОС | Формат | Инструмент |
|----|--------|-----------|
| Windows | `.msix` или installer | `msix` пакет / Inno Setup |
| Linux | `.AppImage`, `.deb` | `flutter_distributor` |
| macOS | `.dmg`, нотаризация | `flutter_distributor` + Apple Developer ID |

В CI сборка Windows и Linux уже есть; добавить job упаковки и загрузку
артефактов в релиз по тегу.

## Чего делать не нужно

- Не переписывать состояние на Riverpod/Bloc ради десктопа: `ChangeNotifier` +
  `InheritedNotifier` держит 393 записи без проблем, а переписывание съест
  время, которое лучше потратить на этапы 1–3.
- Не объединять этот проект с Nebula Archive Inspector в «одну платформу», пока
  оба не доведены до релиза по отдельности.
- Не добавлять WorkManager-аналоги на десктоп: системная задача из
  `tool/desktop/` решает ту же задачу без нативного кода.

## Порядок проверки после каждого этапа

```bash
flutter analyze
flutter test
flutter build linux --release && ./build/linux/x64/release/bundle/vibestack_atlas --headless-sync; echo "exit=$?"
```

Ожидаемый вывод последней команды: `exit=0` при обновлении каталога и `exit=2`,
если данные ещё свежие.
