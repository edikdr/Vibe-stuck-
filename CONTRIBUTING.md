# Как участвовать

Две очень разные вещи живут в одном репозитории, и правила у них разные.

| Что меняешь | Что нужно | Сколько идёт CI |
|-------------|-----------|-----------------|
| записи каталога | только Python 3.10+ | секунды |
| приложение | Flutter SDK (stable) | несколько минут |

## Записи каталога

Правится `data/catalog/*.jsonl` — одна запись, одна строка. Формат полей и все
проверки описаны в [docs/catalog.md](docs/catalog.md).

```bash
python3 tool/build_catalog.py     # пересобрать базу и генерируемый Dart
python3 tool/verify_catalog.py    # тот же контракт, что в CI
```

`assets/catalog.db` — артефакт сборки, он не коммитится: каталог здесь
меняется чаще всего, и бинарник на 3.5 МБ в каждом таком коммите историю
репозитория не украсит. CI собирает его сам перед сборкой приложения.

А вот генерируемый Dart (`lib/i18n/categories.dart`, `lib/app_info.dart`)
коммитится — он должен компилироваться. CI сверяет его с исходниками и падает,
если пересобрать забыли.

Что отклоняется без обсуждения:

- ссылка не на официальный источник (агрегаторы, реф-ссылки, зеркала);
- `http://` вместо `https://`;
- запись-дубль под другим id: имена сравниваются без учёта регистра;
- «полезный ключ» в описании — общие секретные ключи здесь не раздаются,
  запись ведёт на официальную страницу регистрации.

Цены в `pricing` — ориентир на дату `checkedAt`, а не оффер. Указывай
стартовую цену и бесплатный лимит вместе со ссылкой на прайс, чтобы читатель
мог проверить сам.

## Приложение

```bash
bash tool/bootstrap_platforms.sh   # каталог + flutter create + патчи + проверки
flutter analyze                    # должно быть «No issues found!»
flutter test
```

Свежий клон без `assets/catalog.db` не соберётся и не запустит тесты — сначала
`python3 tool/build_catalog.py`. `bootstrap_platforms.sh` делает это сам.

`flutter test` на хосте берёт нативный SQLite у системы, а не у
`sqlite3_flutter_libs`. На Linux и macOS он есть всегда; на Windows его может
не быть, и тогда тесты базы честно скипаются — контракт каталога в CI держит
`tool/verify_catalog.py`, так что дыры это не создаёт.

Полезно знать перед правкой:

- цвета, радиусы и тени — только `lib/theme.dart`; hex-литералов в виджетах
  быть не должно;
- строки интерфейса — `lib/i18n/app_strings.dart`, все три языка сразу
  (en, ru, de), иначе падает `localization_test.dart`;
- `lib/i18n/categories.dart` и `lib/app_info.dart` генерируются — правки
  руками затрёт следующая сборка каталога;
- всё, что приложение знает о платформе и ширине экрана, спрашивается через
  `PlatformInfo` и `Breakpoints`.

## Коммиты и PR

Сообщение коммита — в повелительном наклонении, с областью в начале:
`catalog: add …`, `sync: …`, `ci: …`, `docs: …`.

Один PR — одна тема. Смешанный PR «данные + рефакторинг» ревьюить нечем:
diff данных большой и механический, diff кода маленький и содержательный.

Ветка по умолчанию — `vibe-atlas`, PR открываются в неё.

## Релиз

Релиз собирает и публикует `.github/workflows/release.yml` по тегу:

```bash
git tag v0.7.0 && git push origin v0.7.0
```

В релиз едут сборки под Android, Windows, Linux и macOS плюс сам каталог
(`catalog.db.gz` и `manifest.json`). Установленные приложения подхватывают
новый каталог на ближайшей суточной проверке — переустанавливать ничего не
нужно.
